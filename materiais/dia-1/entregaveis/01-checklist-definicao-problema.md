# Checklist — definição do problema

Preencha antes de pedir qualquer código a um agente. Se você não consegue responder, o agente vai responder por você.

## As quatro perguntas

| Pergunta          | Sua resposta |
| ----------------- | ------------ |
| **Para quem?**    |              |
| **Qual problema?**|              |
| **Qual resultado?** |            |
| **Qual limite?**  |              |

## Como saber se a resposta está boa

- [ ] **Para quem** nomeia pessoas, não áreas vagas. "Analistas do time de cobrança", não "a empresa".
- [ ] **Qual problema** descreve uma dificuldade que existe hoje, não uma solução. "Levo 20 minutos juntando dados de três planilhas", não "preciso de um dashboard".
- [ ] **Qual resultado** descreve o que a pessoa consegue **fazer** ao final, em uma frase que dá para verificar.
- [ ] **Qual limite** diz o que esta versão **não** resolve.
- [ ] Uma pessoa de outra área entende as quatro respostas sem você explicar.

## Exemplo preenchido — TaskWeather

| Pergunta          | Resposta                                                                    |
| ----------------- | --------------------------------------------------------------------------- |
| Para quem?        | Uma pessoa organizando as próprias tarefas do dia, em demonstração interna.  |
| Qual problema?    | Registrar tarefas e consultar o clima obriga a alternar entre aplicativos.   |
| Qual resultado?   | Acessar uma página, criar e concluir tarefas e ver o clima atual da cidade.  |
| Qual limite?      | Sem cadastro real, sem compartilhamento e sem sincronizar com servidor.      |

## Antes de passar para a próxima etapa

- [ ] As quatro perguntas estão respondidas por escrito.
- [ ] O resultado esperado caberia em uma tela.
- [ ] Você sabe dizer quem vai usar isso na segunda-feira seguinte.

> Se a resposta de "qual limite" estiver vazia, o escopo está aberto — e escopo aberto é a causa mais comum de retrabalho.
