# Combinado da área

## 1. O que vale para todo projeto da área

O que passa a ser obrigatório em qualquer projeto feito com agentes:

- [x] Escopo e não escopo escritos antes de começar
- [x] Critérios de aceite verificáveis, escritos antes da implementação
- [x] Regras do projeto (`AGENTS.md`) no repositório
- [x] Registro de entrega com evidência de validação
- [x] Documentação mínima para quem chega depois

**Vale a partir de quando?**

Após o fim do segundo momento do treinamento.

**Vale para projetos já em andamento?** (x) sim ( ) não

## 2. Quem decide o quê

| Decisão                              | Quem decide                                                                                    | Em quanto tempo responde |
| ------------------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------ |
| Aprovar escopo e não escopo          | líder imediato                                                                                 | 1 dia                    |
| Aprovar critérios de aceite          | líder imediato                                                                                 | 1 dia                    |
| Autorizar uma integração externa     | líder imediato em conjunto com as equipes impactadas (pode envolver TI, EdTech, ou outra área) | até 5 dias               |
| Aceitar a entrega                    | líder imediato                                                                                 | 2 dias                   |
| Decidir quando o escopo muda no meio | líder imediato                                                                                 | até 5 dias               |

## 3. Como a evidência chega até a gestão

**Onde ficam os artefatos:**

Repositório Github na conta oficial da EdTech

**O que a gestão recebe quando algo fica pronto:**

- [x] Link do registro de entrega
- [x] Resumo em uma frase do que mudou
- [x] Evidência de validação

**Com que frequência a área revisa os projetos em andamento?**

A cada semana para projetos mais simples, quinzenalmente para entregas mais complexas

## 4. Limites que valem para todo mundo

Combine agora, para não decidir caso a caso depois:

| Assunto                                                | Combinado                                                                           |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Dados de pessoas reais em projeto novo                 | ( ) permitido (x) só com aprovação de **\_\_\_** ( ) não                            |
| Credenciais e chaves de acesso                         | Mantidos fora do Git, em arquivos .env locais, e nunca disponíveis publicamente     |
| Integrações externas que **escrevem** dados            | Podem ser usadas quando usuário é autenticado e tem o nível de permissão necessário |
| Publicar algo fora da rede interna                     | Proibido usar domínios ou contas pessoais para distribuição de código ou Software   |
| O que fazer quando o agente propõe algo fora do escopo | Validar com a liderança quando importante                                           |

## 5. Como saberemos que valeu

Escolha até três sinais que a área vai observar nas semanas seguintes:

- [x] Uma entrega chegou com evidência sem ninguém pedir
- [x] Uma decisão de negócio voltou para a mesa em vez de ser tomada pelo agente

**Quando revisamos isso?** **Três semanas após o segundo momento do treinamento**
